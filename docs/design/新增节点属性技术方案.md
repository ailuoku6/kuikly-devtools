# 为节点新增未声明的 Attr 属性

状态：首期代码已实现，本地逻辑回归通过；Android/iOS 实机及浏览器视觉验证待补。日期：2026-09-25。

实现记录：运行时注册表、inspectProps / setSupported、面板添加入口、CLI/skill 已接入。查询结果按请求连接隔离（server 分配内部 requestId）；单纯断线保留存活节点 token，重连客户端重新查询。验证记录见 `.feature_memo/节点同步与属性状态编辑/changes.md`。下文保留设计依据与验收范围。

## 1. 目标与结论

允许面板与 AI 为选中的节点设置业务 `attr {}` 中没有写过、但该节点实际支持的属性。例如，按钮未设置 `backgroundColor`，仍可在 Devtools 中给按钮设置背景色；文本未设置字号，仍可设置 `fontSize`。

建议采用**运行时属性注册表 + 按需查询支持能力 + 类型化 setter + 执行后真实回读**。新增属性和修改已有属性复用现有编辑传输与回执链路，颜色解析、显示格式及传输格式转换继续留在 server 内部。

这里的“新增”指设置 Kuikly 已定义的属性，不是在 Kotlin 对象上动态创建成员。`state`、`attrState` 仍只能修改插桩暴露的已有可写成员。旧编辑协议保持兼容。

## 2. 源码依据与现有限制

参考本地 KuiklyUI 源码，HEAD 为 `3dfc24e8807d1374c598abf684fa2b7fa5191181`。以下结论来自公共 Kotlin 链路；Android/iOS 最终像素效果仍需真机验证。

| 源码位置（相对 KuiklyUI） | 结论 | 设计影响 |
| --- | --- | --- |
| `core/src/commonMain/kotlin/com/tencent/kuikly/core/base/Props.kt:70` | `setProp` 可向 propsMap 写入新键，随后通知 `didSetProp` | Kuikly 属性容器不要求键预先存在；不能因此认为任意键都有渲染效果 |
| 同文件 `:94` | `removePropCache` 只删除缓存 | 不可用删除缓存冒充原生属性复原 |
| `core/src/commonMain/kotlin/com/tencent/kuikly/core/base/Attr.kt:149` | 宽高等布局属性写 FlexNode | 不能只向 propsMap 写布局键 |
| 同文件 `:215`、`:299`、`:309` | 颜色通过 Color 转为字符串；visibility/touchEnable 的 Boolean 存储为整数 | 用户输入类型、Kuikly API 参数类型、内部存储类型必须区分 |
| 同文件 `:197`、`:353` | zIndex、transform 等有附加语义 | 不通过任意 key/value 通用注入来扩大支持范围 |
| `core/src/commonMain/kotlin/com/tencent/kuikly/core/views/TextView.kt:49` | 文本属性变化同步 shadow，并标记 FlexNode dirty | 使用正式属性通路，保留文本重测量与布局 |
| 同文件 `:261` | fontSize 会处理字体缩放并更新已设置的 letterSpacing | 字号输入定义为 API 逻辑字号，回读可能为缩放后的存储值 |
| `core/src/commonMain/kotlin/com/tencent/kuikly/core/base/VirtualView.kt:41`、`:59` | VirtualView 不创建原生渲染视图，类型判断有明确实现 | 首期不对虚拟节点开放新增属性，不手动创建原生视图 |

当前 Devtools 有三处限制：

1. `KDevtoolsEditing.kt` 的 `editableProps` 只扫描已经采集到的键，`editProp` 要求键在其中，类型也依赖旧值推断。
2. `src/server/values.js` 的 `prepareEdit` 要求键存在于 `node.e[target]`。
3. 面板只有现有属性行，没有查询“该节点还支持哪些属性”的入口。

另一个关键问题是 `KDevtoolsLayout.kt` 会省略默认布局值：例如 flex 为 0、margin 全为 0、positionType 为 RELATIVE。这意味着 **p 中缺少一个键不等于业务从未设置过它**，也不等于它不支持编辑。协议不声称能够恢复源码中 attr 的声明情况。

## 3. 首期范围

对存活、具备实际渲染能力的节点开放以下已注册属性。根据实际 Attr 类型和适配器判断支持性，不按界面展示的 className 字符串判断，也不依赖 KMP 反射。

| 属性组 | 首期属性 | 写入方式与约束 |
| --- | --- | --- |
| 基础外观 | backgroundColor、opacity、visibility、touchEnable | 调用 Attr 对应方法；opacity 为有限数且在 0–1；Boolean 输入 true/false |
| 尺寸 | width、height、minWidth、minHeight、maxWidth、maxHeight | Attr/FlexNode 正式 setter；有限 Float，非负，校验已定义的 min/max 组合 |
| 定位和间距 | top、left、bottom、right、margin、padding | 正式布局 setter；位置/margin 可负，padding 非负；间距支持单数值或四边对象 |
| Flex | flex、flexDirection、flexWrap、justifyContent、alignItems、alignSelf、alignContent、positionType | 复用已有布局适配；flex 的负值语义与当前 Kuikly 保持一致，不额外按 CSS 假定范围；枚举直接由运行时输出 |
| 文本 | text、color、fontSize | 仅 TextAttr 适配范围；调用 text/color/fontSize；fontSize 为正有限 Float |

四边对象是完整设置：未指定的边为 0，提示中明确说明，不隐式合并旧值。全部校验通过后才执行四个 setter。

暂不新增 border/圆角组合、阴影、渐变、transform、百分比布局、图片资源、事件回调、keepAlive 等生命周期属性，也不新增自定义组件的任意 Kotlin 成员。后续每项需补齐 setter、读取、类型约束和平台验证后加入注册表。已有字段的旧编辑能力继续保留，不因这份新增白名单缩小原有范围。

首期不开放虚拟节点新增属性，包括布局属性；其布局参与方式与子节点展开需单独验证。可渲染的组合组件可以按实际 Attr 能力开放，不能仅因 `composeView=true` 就排除。

## 4. 运行时属性定义

新增 `KDevtoolsPropSchema.kt`，每项定义至少包含：

```text
key / label / description
inputType                 面板/AI 的语义类型：color、number、boolean、string、enum、space
wireType                  发给 runtime 的确定类型，例如 argb32、Float、Boolean
constraints / enumValues / examples
supports(view, attr)      节点与平台适用性
read(view, attr)          实际值、是否可读、当前是否在 p 中展示
validate(view, value)     完整校验，不能产生副作用
apply(view, attr, value)  使用 Kuikly API
```

注册表只导出可序列化的描述信息，函数留在设备内。schema 描述有固定版本；server 不允许客户端自己提交类型或约束来绕过设备定义。标准 TextAttr 子类可按继承关系支持；重写 setter 的自定义组件可能改变语义，异常必须反馈，不能承诺事务性回滚。

对已注册字段，新面板和 CLI 的修改也使用同一适配器，避免“新增时 Boolean、后续修改时 0/1”的体验变化。未注册的已有字段继续走 e 提供的旧编辑通路。旧客户端提交的命令仍保留其旧类型语义，不把旧的整型值直接当新 Boolean 命令处理。

## 5. 协议：按需获取、显式选择新能力

保留现有 `Node.e` 的含义与形状，不把全部可新增字段混入 e。runtime 会话增加 capability：`propSchemaV1`。节点属性支持信息按需查询，不随每帧截图在每个节点重复传输。

### 5.1 能力查询

新增设备命令 `inspectProps`，复用现有 requestId、命令队列与 WebSocket 响应关联机制：

```json
{"type":"inspectProps","requestId":"query-1","id":19}
```

响应通过新增 `propSchemaResults` 返回，只给请求方转发；server 缓存用于校验，但打开面板添加入口或执行 CLI 查询时都请求设备刷新。

```json
{
  "requestId":"query-1",
  "ok":true,
  "id":19,
  "schemaVersion":1,
  "schemaToken":"opaque-session-node-generation-token",
  "properties":[{
    "key":"backgroundColor",
    "inputType":"color",
    "wireType":"argb32",
    "reported":false,
    "readable":false,
    "examples":["#80C8FF","0xFF80C8FF"],
    "description":"背景色；八位颜色按 AARRGGBB 解释"
  }]
}
```

示例中的节点 19 仅来自此前按钮树快照；实际操作必须重新定位。`reported` 表示当前 p 是否展示，不能命名为 `explicitlySet`。可读取默认布局值时返回 `readable:true` 和 `currentValue`；原生默认色未知时不编造透明值。

token 绑定会话实例、节点实例代次和属性 schema 版本，不因普通属性值变化失效。节点删除、页面重建或 schema 改变时失效。单纯断线不改变存活节点 token，客户端重连后重新查询；server 重启清空缓存。server 缓存按会话实例与节点代次隔离并清理。设备始终重新验证当前节点和 supports 条件。

### 5.2 设置属性

复用 edit，增加显式 `mode:"setSupported"` 和 schemaToken；省略 mode 保持原有“只能编辑 e 中已存在字段”的路径。

```json
{
  "type":"edit","requestId":"edit-1","id":19,"target":"p",
  "mode":"setSupported","schemaToken":"opaque-session-node-generation-token",
  "key":"backgroundColor","value":"#80C8FF"
}
```

该模式是设置支持的属性（upsert），而不是依赖 p 缺失的原子 insert；避免默认值省略和业务并发写入造成错误判定。server 依据设备 schema 转换，上述示例转为 UInt32 范围内的 JSON 数字 `4286630143`，runtime 构造 `Color(value.toLong())`，再调用 `attr.backgroundColor(...)`。

旧 runtime 未声明 capability 时，server 拒绝新模式，提示重新构建并加载页面，绝不去掉 mode 降级成未知旧命令。新 runtime 同时接受旧编辑命令。新 UI 连接旧 server 时禁用添加入口并明确版本缺失。状态目标 s/as 不接受新模式。

### 5.3 执行与回读

设备线程内依次执行：节点/token 检查 → 支持性检查 → 所有输入校验 → setter → 必要布局 → 从实际对象回读 → 完整树与 editResults 上传 → 触发实时截图调度。

editResults 增加可选 `readback`：`{key, readable, value?, reported}`。该值来自 setter 后的对象，server 按 schema 规范化，不能用提交值代替。新客户端优先使用直接回读；旧客户端仍通过树刷新看到已有字段。

为避免设置默认值后属性行消失，runtime 为当前节点实例记录“Devtools 已触达的注册键”，采集树时补充这些键的实际读取值，包括 flex=0、margin=0 等。只保留键，不存覆盖值；每次采集均重新读取，业务更新仍可见。节点销毁/会话结束清理。无可读值则不伪造 p 项，面板明确显示回读不可用。

错误给出稳定 code 与面向用户的信息，例如 UNSUPPORTED_PROPERTY、INVALID_VALUE、STALE_NODE、SCHEMA_EXPIRED、SETTER_FAILED。非法输入保证 setter 前拦截；setter 抛错可能发生部分副作用，此时重新同步实际值，不宣称已完全还原。超时代表结果未知，不自动重试。token 过期可重新查询，但写命令必须由用户重新提交。

## 6. 颜色和类型转换

server 负责接受 `#RRGGBB`、`#AARRGGBB`、`0xAARRGGBB` 及约定整数格式，统一校验为 32 位 ARGB；六位颜色补 FF，不使用 CSS 的 RRGGBBAA 解释。展示统一为 `0xAARRGGBB`。设备端只校验规范值范围、构建 Kotlin Color，不再解析用户输入的颜色字符串。

新增注册颜色首期只支持数值 ARGB。原生主题 token 的可用集合依赖平台与宿主，未提供验证能力前不在新增入口开放；已有字段的 token 编辑兼容原通路。未来需要时增加单独 colorToken 类型/能力，不能把任意非空字符串都标为合法颜色。

Boolean 使用语义 Boolean 传输，由 Attr 方法转换内部 0/1。Float 在 server 与 runtime 两侧检查有限且转换后仍有限；不能只校验 JavaScript Number。字号展示同时说明“输入为逻辑字号，实际值可能受宿主字体缩放影响”，成功后展示实际回读，不要求它一定等于提交值。

## 7. 面板与 AI 入口

### 面板

属性区增加“添加属性”入口，打开时按需查询，按基础外观/布局/文本分组并可搜索，只列出支持且当前未展示的字段。选择字段后出现值输入、合法值与例子；枚举列出设备返回的完整候选。数字范围、颜色格式、间距缺省边语义均就近提示。

提交沿用 Enter/失焦，Esc 取消；必须输入新值后才允许提交，打开输入框再失焦不提交预填默认值。请求中禁用重复提交。成功且获得真实回读后进入普通属性行，继续保留点击值编辑、hover 虚线边框。非法输入保留或恢复最近合法设备值；新增尚无合法值时取消未应用的临时行并显示错误，不虚构“原值”。

### CLI 与 kuikly-page-inspect skill

已提供以下命令：

```sh
kuikly-devtools inspect props --pager 0 --id 19
kuikly-devtools inspect edit --pager 0 --id 19 --target p \
  --key backgroundColor --value '"#80C8FF"' --set-supported
```

`inspect props` 返回支持列表、约束、当前回读和不可用原因。`--set-supported` 执行前获取最新 schema/token，再发送一次 edit；默认 edit 保持原语义。CLI 不把 server 已排队当成功，必须等待设备结果，并输出规范化后的实际回读。

skill 更新步骤：重新查询会话和节点 → 确认要修改的真实容器（例如 add list 的父按钮，不是文本子节点）→ 查询支持属性 → 按用户授权设置 → 回读并按需查看截图。明确颜色顺序、默认值省略、结果未知不重试和业务覆盖行为，不再把“p 中不存在”统一判定为不能修改。

## 8. 生命周期与兼容边界

修改仅作用于当前运行时实例，不写业务源码、不替换绑定；业务后续更新或页面重建可能覆盖结果。此行为在 UI/skill 的操作说明中交代。

本期不提供“恢复为从未设置”和删除属性功能。已有可读旧值可再次写回，但这不等价于移除声明；渲染属性未设置时的默认值不总能可靠读取。重置功能必须有单独的属性级 reset 适配器，不能使用 null 或 removePropCache 通用实现。

查询超时、节点已删除、页面重建以及多个面板并发修改时，重新读取真实状态。设置采用最后实际执行写入生效，不承诺编辑锁或 CAS。schemaToken 防止旧节点误写，不用于解决同一存活节点的业务并发覆盖。

## 9. 实施拆分

1. Runtime：新增属性注册表、能力查询、节点实例 token、setSupported 分支、直接回读；补充默认值采集与实例清理。涉及 KDevtoolsEditing/Layout/Tree/Session。
2. Server：values.js 按 schema 校验与规范化；hub/panel 转发查询和回执、能力判断、缓存清理。命令响应与原有请求方关联，不将成功入队冒充执行成功。
3. UI：protocol/store 增加 schema 查询和结果；Inspector 添加入口并复用行编辑；editHints 使用注册表约束，旧字段保留既有提示。
4. CLI/skill：新增 inspect props 与 --set-supported，更新帮助、流程及中英文使用文档。
5. 回归后重新生成 UI 产物；runtime 需要业务重新插桩构建、加载，不能只更新 server 就声称已支持。

## 10. 验证与验收

| 层级 | 必须覆盖 |
| --- | --- |
| Server 单测 | 缺少旧值时仍依据 schema 转换；ARGB 透明度/边界/非法字符串；Boolean、Float 溢出、枚举与四边对象；无 capability 拒绝；不能由请求伪造 schema |

| 生命周期与兼容 | 节点 id 复用、页面重建、重连、失效 token、查询/编辑超时；旧客户端+新 runtime、新客户端+旧 runtime；未注册旧字段编辑保持可用 |
| UI/CLI | 属性搜索/选择、合法值提示、Enter/blur 单次提交、Esc、错误恢复；AI 查询→写入→设备回执→读回完整链路 |
| 截图回归 | 编辑持续触发状态上报时实时截图继续；截图上传仍附最新树；不要求异步截图与树严格同一像素时刻 |
